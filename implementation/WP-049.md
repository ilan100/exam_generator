# WP-049 — Classification-Avoidance Generation Strategy

## 1. Objective

WP-048 established that the dominant classification-ambiguity family is not currently a missing safety/detection mechanism. For `Globus Pallidus`, `Caudate Nucleus`, and `Nucleus Accumbens`, the existing `GroundingValidator` and `MCQValidator` already reject genuinely ambiguous candidates.

The remaining problem is generation reliability:

```text
LLM generates an under-specified classification predicate
        ↓
multiple answer choices satisfy the predicate
        ↓
existing validators correctly reject it
        ↓
retry
        ↓
same or similar failure may repeat
        ↓
3-attempt budget may be exhausted
```

WP-049 must determine whether a **small, evidence-based change to generation guidance** can reduce these failures without adding another post-generation detector.

Primary targets:

```text
Globus Pallidus
Caudate Nucleus
Nucleus Accumbens
```

`Basillar artery` is explicitly out of the primary experiment because WP-048 identified it as a separate, unresolved subclass.

## 3. Core Architectural Question

> Can generation guidance make the LLM reliably avoid generic classification predicates for targets whose broader category contains multiple plausible answer concepts, without introducing a new semantic detector?

The desired flow is:

```text
target
   ↓
identify target-specific property
   ↓
verify property is supported by authoritative evidence
   ↓
generate question testing that property
   ↓
existing validators provide final safety
```

The undesired flow is:

```text
target
   ↓
generic category membership
   ↓
multiple supported answers
   ↓
validator rejection
   ↓
retry
```

## 9. Candidate Strategy

A possible instruction concept is:

```text
When the target belongs to a broader category containing multiple
candidate concepts, do not ask a generic category-membership question.
Instead, generate a question based on a target-specific property that
is explicitly supported by the authoritative evidence and distinguishes
the target from the available alternatives.
```

This is a **starting hypothesis only**. Inspect the actual prompt and formulate the smallest appropriate wording.

The instruction must not encourage invented facts.

## 10. Evidence-Grounded Specificity

The revised guidance must preserve the source hierarchy:

```text
student summaries = sole factual grounding authority
course_book.pdf = secondary consistency check
historical questions = style/structure reference only
```

Target specificity means:

```text
select a distinctive property supported by evidence
```

not:

```text
invent a distinctive property
```

---

## 11. Do Not Force Identity Questions

Do not solve the problem by requiring every question to be:

```text
Which of the following is X?
```

Target-specificity means a unique predicate, not necessarily an identity-by-name question.

Valid target-specific predicates may concern:

```text
function
location
anatomical relation
source
role
specific property
```

provided the authoritative evidence supports them and the predicate uniquely identifies the target among the actual choices.

## 24. Possible Outcomes

### Outcome A — Improvement

If classification ambiguity clearly decreases without unacceptable regression:

```text
ACCEPT
```

the prompt modification and document why it works and its limitations.

### Outcome B — No Meaningful Improvement

Do not keep adding prompt instructions indefinitely.

Document that prompt-only intervention was insufficient and recommend the next architectural option.

### Outcome C — Improvement With Regression

If ambiguity decreases but another important metric deteriorates, investigate causality. Reject the change if the regression cannot be acceptably isolated.

### Outcome D — Prompt Overfitting

If the change only works for the three named targets or effectively encodes their characteristics, reject it.
