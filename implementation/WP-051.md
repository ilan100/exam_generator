# WP-051 — Target Evidence Sufficiency / Questionability Study

## 1. Objective

WP-050 established that the current classification-ambiguity problem is not uniformly a generation problem.

The investigation found:

```text
Globus Pallidus
    ↓
a genuinely target-specific property exists in the authoritative evidence

Caudate Nucleus
    ↓
no evidence-supported unique property found

Nucleus Accumbens
    ↓
no evidence-supported unique property found
```

WP-050 therefore concluded that candidate-uniqueness machinery should **not** be implemented.

The next architectural question is:

> **Can the system determine, before generation, whether a selected target has sufficient authoritative, target-specific evidence to support a valid and non-ambiguous question?**

The purpose of WP-051 is to investigate this question.

The desired architectural direction is:

```text
Target selection
        ↓
Evidence sufficiency / questionability assessment
        ↓
SUFFICIENT
        ↓
Generate question

or

INSUFFICIENT
        ↓
Do not spend generation attempts on this target
        ↓
Select another eligible target
```

This WP is primarily an **architectural investigation**.

Do not implement production target-selection changes unless the investigation establishes that a safe, general, deterministic mechanism is justified.

---

# 2. Why This WP Is Needed

The current behavior can be:

```text
target selected
    ↓
LLM attempts question
    ↓
predicate is generic/shared
    ↓
validator rejects
    ↓
retry
    ↓
same fundamental problem may repeat
```

WP-050 showed that, for some targets, this is not merely because the LLM failed to find the right property.

The authoritative evidence itself may not contain a sufficiently target-specific fact.

Therefore the architecture should investigate whether the system can identify such targets **before generation**.

The goal is not:

```text
guarantee every target can produce a question
```

The goal is:

```text
avoid wasting generation attempts on targets
for which the authoritative evidence is clearly insufficient
for the current question-generation requirements.
```

---

# 3. Architectural Principle

The investigation must preserve:

```text
Fail closed on validity.
Relax on diversity.
```

For evidence sufficiency:

```text
SUFFICIENT
```

should mean:

> The available authoritative evidence provides enough target-specific information to justify attempting generation.

It must **not** mean:

```text
the model will definitely succeed
```

Likewise:

```text
INSUFFICIENT
```

must mean:

> The available evidence does not safely provide enough target-specific information for the current generation requirements.

Do not classify a target as insufficient merely because one particular generation attempt failed.

# 7. First Question: What Does "Sufficient Evidence" Mean?

Before designing any implementation, define the concept operationally.

The investigation must determine whether evidence sufficiency can be expressed in deterministic terms such as:

```text
target has at least one target-specific factual statement
```

or:

```text
target has at least one non-enumerative evidence statement
```

or:

```text
target has at least one evidence-supported relationship
```

or some combination.

Do not assume any one of these is sufficient.

Evaluate them against real examples.

---

# 8. Distinguish Evidence Sufficiency From Question Success

These are different concepts.

```text
Evidence sufficiency
    =
enough source information exists to attempt generation.

Generation success
    =
LLM actually produced a valid question.
```

A target can have:

```text
SUFFICIENT evidence
+
generation failure
```

and a target can have:

```text
INSUFFICIENT evidence
+
an apparently successful question
```

The second case must be treated carefully because acceptance does not automatically prove source adequacy.

# 11. Separate Enumeration Evidence From Target-Specific Evidence

This distinction is central.

### Enumeration evidence

Example:

```text
Striatum contains:
Caudate Nucleus
Nucleus Accumbens
Putamen
```

This tells us:

```text
membership
```

but does not necessarily provide a target-specific predicate.

### Target-specific evidence

Example:

```text
Globus Pallidus
    ↓
specific thalamus-suppression role
```

This may support a target-specific question.

The investigation must determine whether this distinction can be identified deterministically.

# 13. Target-Specificity vs. Mere Mention

A target appearing in a sentence does not automatically make the sentence target-specific.

Example:

```text
The basal nuclei participate in reward and decision-making.
```

This sentence may mention the target's broader category but does not establish:

```text
Caudate Nucleus specifically has property P.
```

The investigation must distinguish:

```text
target mentioned in evidence
```

from:

```text
property explicitly attributed to target
```

---

# 14. Category-Level Statements

Investigate how frequently the source evidence contains statements about:

```text
the category as a whole
```

rather than:

```text
one named target
```

These statements should not automatically count as target-specific evidence.

Example:

```text
Basal nuclei participate in motor function.
```

must not be treated as:

```text
Globus Pallidus specifically participates in motor function
```

unless the authoritative evidence explicitly supports that attribution.

---

# 15. Shared-Property Evidence

A target may have an explicit property but still be unsuitable if the same property is explicitly assigned to several candidates.

Therefore investigate:

```text
target-specific evidence
```

and:

```text
shared evidence
```

separately.

The goal is not merely:

```text
Does target have a property?
```

but:

```text
Does target have enough evidence for a property
that can plausibly support a unique question?
```

---

# 16. UNKNOWN Must Remain UNKNOWN

Do not infer:


```text

```

Both are unsafe.

Use:

```text

```

where appropriate.

This is mandatory.

```text
does not describe the category collectively.
```

These are investigation candidates only.

Do not implement them blindly.

# 55. Final Instruction to Claude

**WP-051 is an architectural investigation into evidence-aware target eligibility.**

Do not try to make every target generate a question.

Do not try to make the LLM invent target-specific facts.

Do not solve the problem by:

```text
more prompt rules
more retries
LLM judges
semantic post-generation parsing
external medical knowledge
external ontology
new post-generation validators
```

The central question is:

> **Can the existing authoritative evidence tell us, before generation, whether a target has enough target-specific information to make generation worth attempting?**

The desired architecture, if justified, is:

```text
Category
   ↓
Existing questions / coverage
   ↓
Candidate target
   ↓
Authoritative evidence sufficiency
   ↓
Eligible?
   ├── NO  → do not spend generation attempts
   │          select another eligible target
   │
   └── YES → QuestionTarget
                ↓
             generation
                ↓
             existing validators
```

The critical distinction remains:

```text
evidence exists
        ≠
evidence is target-specific
        ≠
evidence is uniquely identifying
        ≠
generation is guaranteed to succeed
```

WP-051 should determine exactly which of these can be established safely.

Preserve:

```text
student summaries = sole factual authority
course_book.pdf = secondary check only
historical Excel = style/structure reference
English-first
0–3 existing questions
one category per run
one new question per run
three-attempt budget
WP-044
WP-046
WP-047
existing validators
existing schemas
```

Do not change those product or architectural rules.

A successful WP-051 may produce **no code**.

A strong result would be:

```text
We found a simple deterministic signal that safely identifies
targets for which generation is worth attempting.
```

A strong negative result would be:

```text
No safe deterministic signal can distinguish questionable
targets from non-questionable targets with the current evidence
representation.
```

Both are valuable.

The unacceptable result is a heuristic that appears to improve acceptance by silently discarding difficult targets or treating missing evidence as false evidence.

**WP-051 is complete only when the repository contains:**

