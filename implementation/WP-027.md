WP-001 through WP-026 are complete.

WP-026 improved target-aware MCQ framing and preserved WP-025 diversity.

However, human review found a more serious correctness problem:

    an invalid MCQ can pass all validators and enter the exam.

The primary example was accepted question #23:

    Which system is part of the peripheral nervous system?

The designated correct answer was:

    somatic nervous system

but another answer choice was:

    autonomic nervous system

The exact authoritative evidence supplied to GroundingValidator stated that
the PNS divides into BOTH:

    autonomic
    somatic

Therefore the candidate had two correct answers.

Nevertheless GroundingValidator returned a passing result.

The diagnostic established that this was not merely an isolated enumeration
problem:

    30 CLEAR_SINGLE_ANSWER
    2 CONFIRMED_SECOND_CORRECT_ANSWER
    2 POSSIBLE_SECOND_CORRECT_ANSWER
    1 separate insufficient-evidence concern

among the 35 accepted WP-026 questions.

The architectural diagnosis found:

- GroundingValidator already owns the invariant that no other answer is
  equally supported;
- it already receives authoritative evidence;
- its response model already has a holistic
  `other_answers_not_equally_correct` field;
- the weakness is that the LLM can make one holistic determination without
  explicitly evaluating each answer option;
- MCQValidator is intentionally evidence-free and should remain primarily
  responsible for MCQ structure;
- QualityValidator correctly remains wording/style focused.

Recommended direction:

    generation improvement
        +
    stronger independent GroundingValidator

with zero additional LLM calls.

---

# 1. Objective

Prevent factual false acceptance caused by a distractor that is also a
correct answer according to authoritative student-summary evidence.

Strengthen the invariant:

    exactly ONE answer choice is factually correct according to the supplied
    authoritative evidence.

Grounding must no longer establish this only through a single holistic
boolean.

It must explicitly evaluate the factual status of every answer option.

The desired flow is:

    candidate
        ↓
    independent grounding evidence retrieval
        ↓
    evaluate question premise
        ↓
    evaluate answer 1 against evidence
    evaluate answer 2 against evidence
    evaluate answer 3 against evidence
    evaluate answer 4 against evidence
        ↓
    deterministically derive whether exactly one answer is supported
        ↓
    normal GroundingValidationResult
        ↓
    existing acceptance policy

Do NOT add another validator.

Do NOT add another LLM call.

---

# 2. Preserve Validator Responsibilities

Keep the existing five-validator architecture.

## GroundingValidator

Responsible for factual support against authoritative student-summary
evidence, including:

- question premise supported;
- designated correct answer supported;
- each answer option's factual relationship to the question;
- no non-designated answer is also correct;
- no unsupported factual claims.

## MCQValidator

Remains responsible for structural MCQ quality such as:

- exactly four answers;
- one-best-answer structure as presented;
- plausible distractors;
- structural ambiguity;
- exam construction.

Do NOT add student-summary retrieval to MCQValidator in WP-027.

## CategoryValidator

Unchanged.

## QualityValidator

Unchanged.

## TextbookValidator

Unchanged.

Do not collapse factual grounding and structural MCQ validation into one
validator.

---

# 3. New LLM-Facing Per-Option Grounding Contract

Extend the LLM-facing grounding response contract so every answer option is
evaluated explicitly.

Use the smallest typed structure consistent with the existing model style.

Conceptually, introduce something similar to:

    GroundingAnswerAssessment

with fields representing at least:

    answer_index
    supported_as_correct
    evidence_refs
    reason

Exact naming should follow repository conventions.

The grounding LLM-facing response should contain exactly four such
assessments, corresponding to answer choices 1..4.

The LLM must explicitly determine for EACH answer:

    Does this answer correctly answer THIS QUESTION according to the supplied
    authoritative evidence?

This is not merely:

    Is this answer text mentioned somewhere in the evidence?

An answer can state a true fact but still not correctly answer the question.

Conversely, a distractor that correctly satisfies the exact relationship
asked by the question must be treated as another correct answer.

---

# 4. Deterministic Application-Side Derivation

Do not trust the LLM to independently summarize its four assessments into an
inconsistent final boolean.

After receiving and validating the four per-option assessments, derive the
critical grounding fields deterministically where possible.

Conceptually:

    supported_answer_indices =
        every answer assessment where supported_as_correct == True

Then:

    correct_answer_supported =
        candidate.correct_answer in supported_answer_indices

and:

    other_answers_not_equally_correct =
        no non-designated answer is in supported_answer_indices

and grounding cannot pass unless:

    designated correct answer is supported
        AND
    no other answer is supported as correct
        AND
    all other existing grounding requirements pass

Do not allow a response equivalent to the WP-026 #23 failure:

    option 1 supported = true
    option 3 supported = true

but:

    other_answers_not_equally_correct = true

The application should make such an inconsistent state impossible or reject
it deterministically.

Prefer deriving redundant summary booleans locally rather than asking the LLM
to reproduce them independently.

Preserve existing public `GroundingValidationResult` semantics as much as
reasonably possible.

---

# 5. Exactly Four Assessments

Strictly validate the per-option response.

Require:

- exactly four assessments;
- indices correspond exactly to 1, 2, 3, 4;
- no duplicates;
- no missing indices;
- no index 0;
- no negative index;
- no index >4.

Malformed/inconsistent option-assessment structure must fail closed.

Use the smallest appropriate existing/new error semantics.

Do not silently repair, reorder ambiguously, invent missing assessments, or
guess intended indices.

Deterministic sorting after validating a complete unique {1,2,3,4} set is
acceptable if useful.

---

# 6. Evidence Provenance

Reuse WP-022's local evidence-reference architecture.

The grounding LLM must use call-local:

    [Evidence N]

references.

Per-option assessments may cite:

    evidence_refs: list[int]

These refs must be:

    bounds checked
        ↓
    deterministically resolved
        ↓
    canonical chunk IDs

Do NOT ask the LLM to reproduce canonical evidence chunk IDs.

Invalid refs remain fail-closed and continue to interact with WP-021's
existing provenance-retry behavior.

Do not weaken provenance validation to solve factual correctness.

---

# 7. Evidence Semantics for Unsupported Answers

Do not require fabricated evidence for an answer judged unsupported.

For an unsupported distractor, `evidence_refs` may legitimately be empty.

Its reason should explain why the supplied evidence does not establish that
answer as correct for the exact question.

For a supported answer, require evidence sufficient to justify the positive
support judgment.

Define and test the invariant clearly.

Do not force the LLM to cite irrelevant evidence merely so every option has a
citation.

---

# 8. Grounding Prompt

Strengthen `prompts/validation/grounding.txt`.

The prompt must require explicit evaluation of:

    Answer 1
    Answer 2
    Answer 3
    Answer 4

against:

    the exact question
        +
    authoritative student-summary evidence.

It must explicitly warn:

- do not stop after proving the designated answer;
- do not assume distractors are false because they were labeled as
  distractors by the generator;
- generator claims are untrusted;
- a distractor may also be correct;
- if another option correctly answers the question, report it as supported;
- true sibling members of a classification must not be rejected merely
  because they are non-designated choices;
- evaluate every option independently before concluding the candidate has
  one factual answer.

The prompt should make the #23 reasoning failure difficult:

    "PNS includes somatic and autonomic"

must result in both corresponding membership answers being assessed as
supported for a bare PNS-membership question.

---

# 9. Do Not Trust Candidate Labels

Grounding receives a CandidateQuestion containing an intended correct answer.

That label is a claim from generation, not factual authority.

Grounding must treat:

    candidate.correct_answer

as:

    the answer the generator INTENDS to be correct

not:

    proof that this answer is uniquely correct.

The validator must independently evaluate all four options.

Preserve this trust boundary explicitly in code comments/prompt/docs where
appropriate.

---

# 10. Grounding Retrieval Investigation

The diagnostic identified a possible secondary weakness:

current grounding retrieval is based on approximately:

    category
    + question
    + intended correct-answer text

while distractor text is deliberately excluded.

For question #23 this was NOT the proximate cause:

the exact evidence proving the autonomic distractor correct was successfully
retrieved and supplied.

Therefore do NOT automatically redesign retrieval.

Before changing it, test whether the current retrieval strategy gives the
validator adequate evidence to judge all four options.

Use the WP-026 accepted-question cases and focused tests/diagnostics.

If evidence relevant to a distractor can systematically be missed because its
text is absent from the retrieval query, make the SMALLEST grounding-specific
query improvement necessary.

Possible direction to investigate:

    category
    + question
    + all four answer texts

or another compact query representation.

But this is NOT pre-authorized as the implementation.

Only change retrieval-query construction if evidence demonstrates it is
needed.

If changed:

- keep retrieval independent;
- keep student summaries as sole primary authority;
- do not change TF-IDF implementation;
- do not change chunking;
- do not add embeddings;
- document why the previous query was insufficient;
- add focused regression tests.

---

# 11. Generation-Side Complementary Fix

Strengthen the WP-026 generation prompt narrowly.

Generation must explicitly avoid using another evidence-supported answer as a
false distractor.

In particular:

If the assigned target/evidence says:

    X includes A and B

then a bare question:

    Which is part of X?

must NOT designate A as correct while presenting B as incorrect.

Likewise, for non-enumeration facts:

if supplied evidence supports a distractor as also satisfying the exact
question, that distractor must not be used.

Strengthen the rule conceptually to:

    every distractor must be false for the EXACT relationship asked by the
    question according to the supplied factual evidence.

Do not limit this rule only to enumeration targets.

The diagnostic found similar false-acceptance patterns outside enumeration
targets.

This generation change REDUCES occurrence probability.

Grounding remains the independent correctness backstop.

Do not rely on generation alone.

---

# 12. No New LLM Calls

WP-027 must not add another validation call.

Use:

    existing generation call
    existing grounding call

with stronger contracts/prompts.

Per-option grounding happens inside the existing grounding structured-output
call.

Expected additional cost should therefore come only from:

- somewhat larger grounding structured output;
- possibly somewhat larger grounding input if a justified retrieval-query
  adjustment changes retrieved evidence.

Report token/cost implications where observable.

---

# 13. Failure Semantics

A candidate with:

    designated answer supported
        BUT
    another answer also supported as correct

is a NORMAL CANDIDATE REJECTION.

It is not an operational failure.

Grounding should return a normal result equivalent to:

    passed = false

because:

    other_answers_not_equally_correct = false

Existing WP-013/WP-019 production semantics should then consume the current
attempt and generate another candidate against the SAME QuestionTarget.

Do not add a new retry mechanism.

Do not increase:

    generation.max_generation_attempts

Do not throw an operational exception merely because two answers are
factually correct.

---

# 14. Distinguish Verdict Failure from Contract Failure

Keep these separate.

## Candidate-quality failure

Example:

    options 1 and 3 are both supported as correct

Result:

    normal GroundingValidationResult
    passed = false

## Operational/contract failure

Examples:

- missing option assessment;
- duplicate option index;
- invalid evidence ref;
- malformed structured response;
- impossible response shape.

Use existing WP-020/WP-021 recovery/error semantics where applicable.

Do not convert factual rejection into an exception.

---

# 15. Public Grounding Result Compatibility

Preserve downstream contracts as much as possible.

Existing consumers depend on:

    GroundingValidationResult
    grounding.passed
    grounding.grounded
    grounding.correct_answer_supported
    grounding.other_answers_not_equally_correct
    grounding.evidence_chunk_ids
    grounding.reason
    grounding.confidence

Do not broadly refactor production/audit/orchestration merely to expose the
new LLM-facing structure.

If per-option assessments are useful for audit/human review and can be added
with a small justified contract extension, evaluate that explicitly.

However, do not expand public/audit schemas merely because the LLM-facing
response became richer.

Prefer:

    richer internal LLM response
        ↓
    deterministic conversion
        ↓
    stable public GroundingValidationResult

unless preserving per-option details downstream has a clear diagnostic/user
value.

Document the decision.

# 18. Positive Regression Cases

Do not overcorrect.

Add cases where distractors contain true anatomical terms/facts but do NOT
correctly answer the exact question.

Example concept:

Evidence describes:

    A has property X
    B has property Y

Question:

    Which structure has property X?

Answers:

    A   <- correct
    B
    C
    D

B may be a real structure with a true property elsewhere in the evidence, but
it does not satisfy property X.

Expected:

    only A supported_as_correct
    passed = true

This distinction is critical.

WP-027 must not reject every distractor merely because the distractor itself
is a real anatomical entity or because some statement about it is true.

# 33. Acceptance Criteria

WP-027 is complete when:

1. Grounding explicitly evaluates all four answer options.

2. Per-option evaluation uses a typed structured-output contract.

3. Exactly four unique answer assessments are required.

4. Each assessment corresponds to answer indices 1..4.

5. Positive support can carry local evidence refs.

6. Local refs resolve deterministically to canonical evidence IDs.

7. Invalid refs remain fail-closed.

8. `correct_answer_supported` is derived deterministically.

9. `other_answers_not_equally_correct` is derived deterministically.

10. A second evidence-supported answer forces grounding failure.

11. Such failure is a normal candidate rejection, not an operational error.

12. Existing three-attempt production semantics handle regeneration.

13. No new retry mechanism is added.

14. No attempt limit is increased.

15. MCQValidator remains evidence-free and structurally focused.

16. QualityValidator responsibility remains unchanged.

17. Generation explicitly forbids evidence-supported false distractors.

18. Generation remains target-faithful.

19. WP-026 #23 is covered by a regression test.

20. Additional #8/#14/#32/#30 shapes receive appropriate regression coverage.

21. Positive cases prevent over-rejection.

22. WP-020/021/022 recovery/provenance behavior remains intact.

23. Retrieval-query adequacy is explicitly evaluated.

24. Retrieval is changed only if evidence justifies it.

25. Full regression passes.

26. Focused live test is performed if credentials are available.

27. Persisted WP-026 suspicious cases are re-evaluated where practical.

28. One full 2-per-category acceptance run is performed if credentials are
    available.

29. Accepted questions receive false-acceptance human review.

30. Same-category diversity is re-evaluated.

31. Reliability/cost trade-off is reported.

32. TF-IDF remains unchanged.

33. No embeddings/vector DB is introduced.
