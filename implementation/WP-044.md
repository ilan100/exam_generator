# WP-044 — Structural Generation Constraints for Evidence Shape and Target Role

## 1. Objective

WP-043 established two important facts:

1. The deterministic evidence-sufficiency mechanism and source-span recovery work correctly.
2. The generation layer still does not reliably transform the recovered evidence and target-role information into a valid question whose answer is the selected target.

The WP-043 live pilot produced:

```text
WP-040: 11/12
WP-041:  9/12
WP-043:  5/12
```

The two principal failure modes are now:

### Problem A — Enumeration-shaped evidence

`Corpos Striatum` now receives genuine surrounding evidence, but that evidence has the shape:

```text
Basal nuclei contain several sub-structures
```

This encourages generation of questions such as:

```text
Which of the following is a sub-structure of the basal nuclei?
```

while the required answer is:

```text
Corpos Striatum
```

The problem is that multiple entities may satisfy the question.

### Problem B — Source-role evidence

`Basillar artery` is correctly detected as a source/upstream entity.

However, generation still frequently produces questions whose semantic role corresponds to the downstream entity.

The current source-role information is only an instruction in the prompt and is not reliably followed.

---

# 2. Primary Goal

Determine whether the existing generation architecture can encode these constraints **structurally**, rather than relying on increasingly strong free-text prompt instructions.

The target architecture should move toward:

```text
Target
   +
Evidence
   +
Evidence shape
   +
Target semantic role
   +
Required answer identity
        ↓
Structured generation constraints
        ↓
Question generation
        ↓
Existing validation
```

The goal is not to replace the LLM.

The goal is to constrain the LLM so that it generates only question forms compatible with the evidence and target.

---

# 7. Problem A — Enumeration-Shaped Evidence

The first generation constraint concerns evidence whose structure is effectively:

```text
X contains several structures:
A
B
C
...
```

where the selected target is one member:

```text
Target = B
```

A generic question:

```text
Which of the following is a structure contained in X?
```

is invalid if:

```text
A
B
C
```

are all correct.

---

# 8. Detect Enumeration Shape Conservatively

Investigate whether enumeration-shaped evidence can be identified deterministically from the existing evidence structure.

Possible signals may include:

```text
contains several...
includes...
consists of...
the following...
```

or existing source formatting.

Do not create a broad semantic classifier.

The detection should be:

* deterministic;
* narrow;
* explainable;
* testable.

If the existing source representation already provides enough structure, reuse it.

---

# 9. Do Not Overgeneralize Enumeration Detection

Do NOT build a generic NLP classifier for:

```text
enumeration
```

in WP-044.

We need to solve the demonstrated problem first.

If a safe deterministic signal cannot be established, record that limitation instead of introducing a complex mechanism.

---

# 10. Enumeration Generation Constraint

When:

```text
evidence_shape = ENUMERATION
```

and:

```text
target = one member of the enumeration
```

the generation plan must prevent a generic membership question unless the target is uniquely distinguished.

Conceptually:

```text
INVALID:
"Which of the following is a sub-structure of X?"

when multiple options are members of X.
```

Instead, generation should be required to construct a question that uniquely identifies the target using additional evidence-supported information.

For example, if the source explicitly provides a distinguishing property:

```text
Which structure is associated with <unique source-supported property>?
```

then that may be valid.

The property must come from the evidence.

Do not invent one.

---

# 11. Safe Failure for Enumeration

If the evidence only says:

```text
X contains:
A
B
C
```

and provides no distinguishing fact about:

```text
B
```

then the system should prefer:

```text
target unavailable for safe generation
```

over generating:

```text
Which is a part of X?
```

This follows the established principle:

> **Prefer missing over wrong.**

A lower acceptance rate is preferable to a medically ambiguous question.

---

# 12. Problem B — Source-Role Generation

The second problem concerns:

```text
Target = source/upstream entity
```

Example:

```text
Basillar artery
    ↓

    ↓
Superior Cerebellar Artery
```

The generator must be prevented from treating the target as though it were the downstream entity.

---

# 14. Relationship Must Be Source-Grounded

The relationship must come from:

```text
authoritative source evidence
```

not from:

```text
LLM inference
```

and not from:

```text
external medical knowledge
```

For example, if the source says:

```text
Basillar artery gives rise to Superior Cerebellar Artery
```

the relationship may be represented.

If the source does not establish the relationship clearly:

```text
do not invent it.
```

---

# 15. Generation Must Use the Relationship

The generation prompt should receive a structured constraint equivalent to:

```text
The question must test the target's source/origin relationship.

The correct answer must be the target.

Do not ask a question whose correct answer is the downstream entity.
```

But the important change is:

> This should be represented as part of the generation blueprint/contract, not merely as another paragraph of natural-language advice.

The exact prompt wording is secondary.

# 20. Important Design Principle

The application should determine:

```text
WHAT relationship may be tested
```

The LLM should determine:

```text
HOW to phrase the question
```

For example:

```text
Application:
Target = Basillar artery
Relationship = source/origin of Superior Cerebellar Artery

LLM:
"What artery gives rise to the Superior Cerebellar Artery?"
```

This is the desired division of responsibility.

---

# 21. Do Not Hard-Code Question Wording

Do NOT implement:

```text
if source role:
    question = "Which artery gives rise to..."
```

That would be brittle.

Instead encode:

```text
allowed relationship:
source/origin
```

and allow the existing generation system to produce appropriate wording.

# 33. Acceptance Criteria

WP-044 should be considered successful only if all of the following hold.

### A. Enumeration constraint

The system no longer routinely generates ambiguous generic membership questions for enumeration-shaped evidence.

### B. Source-role constraint

The system reliably generates question forms compatible with the target's source/upstream role.

### C. Target identity

The generated answer remains the selected target.

### D. Grounding

Existing grounding validation remains strict and passes valid candidates.

### E. English-first

When English exists:

```text
English is used.
```

No Hebrew should appear merely because the evidence is Hebrew.

### F. Regression

All existing tests pass.

### G. Pilot

Acceptance improves materially from WP-043's:

```text
5/12
```

without relaxing validators or increasing the retry budget.
