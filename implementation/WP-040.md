# WP-040 — Target-Aware Generation for Named Concepts

## Context

Read completely:

- docs/MASTER_PROJECT_BRIEF.md
- docs/ARCHITECTURE.md
- docs/PROJECT_STATUS.md
- implementation/WP-038_ARCHITECTURE_REVIEW.md
- implementation/WP-039_COMPLETION_REPORT.md
- implementation/WP-039_ARCHITECTURE_REVIEW.md

Also inspect the current implementation and tests before making any changes.

WP-039 successfully fixed the trailing-truncation problem at the correct architectural layer.

The latest live pilot produced:

- 11/12 accepted questions;
- truncation-induced coverage failure was fixed;
- complete concept identities are now reaching planning;
- full regression: 1304/1304.

However, manual target alignment was only approximately 45%.

The important observed failure pattern is:

```text
Selected concept:
Corpos Striatum

Generated correct answer:
"involved in executing planned motor movements"
```

and:

```text
Selected concept:
Medial Lemniscus Tract

Generated correct answer:
"advanced sensations"
```

These answers may be factually related to the selected concept, but they do not identify the selected concept itself.

This creates a fundamental problem:

```text
Concept selected
      ↓
Evidence correctly anchored
      ↓
Question generated
      ↓
Answer describes a property/function of the concept
      ↓
Answer does not identify the selected concept
      ↓
Coverage cannot reliably establish that the selected concept was tested
      ↓
Concept may be selected again
```

WP-040 must address this problem at the **generation layer**.

---

# 1. Objective

Improve generation so that when the planner selects a named concept, the generated question's correct answer actually identifies that selected concept.

The desired behavior is:

```text
Selected concept:
Corpos Striatum

Question:
<question asking which structure ...>

Correct answer:
Corpos Striatum
```

rather than:

```text
Selected concept:
Corpos Striatum

Question:
<question asking about its function>

Correct answer:
"involved in executing planned motor movements"
```

The objective is:

> Make target alignment a property of the generated question rather than something that must be repaired by downstream validation.

---

# 2. Critical Architectural Principle

Do NOT solve this by adding another validator/retry loop.

Do NOT implement:

```text
Generate
   ↓
Target-alignment validator
   ↓
Reject
   ↓
Generate again
```

as the primary solution.

This would consume the existing bounded generation-attempt budget and recreate the exact reliability problem the project has been trying to avoid.

Instead:

> Change the generation contract/prompt so the model produces a target-aligned question in the first place.

---

# 3. First Investigate the Existing Generation Path

Before changing code, inspect the actual implementation.

Determine:

1. Where the selected concept is passed to generation.
2. How the selected concept is represented in the generation prompt.
3. What evidence is supplied.
4. What instructions currently govern the correct answer.
5. Whether the prompt currently permits functional/property questions even when the target is a named entity.
6. Whether there is already any target-type information.
7. Whether the generated candidate model has enough information to distinguish:
   - named entity target;
   - functional target;
   - relationship target;
   - other target.

Do not assume the answer.

Report the actual current behavior before implementing the change.

# 5. Target Type

Investigate whether the existing concept inventory already contains enough information to classify a selected concept.

The preferred solution is to use existing information.

Do NOT introduce an LLM-based target classifier.

Do NOT use semantic classification.

Do NOT create a large manually maintained taxonomy.

If target type information does not currently exist, determine the smallest deterministic representation that can be introduced safely.

Prefer:

```text
named_entity_target = true
```

or an equivalent minimal internal distinction.

Avoid public API changes unless absolutely necessary.

---

# 6. Named Concept Definition

For this WP, a named concept means a concept that represents an identifiable entity, such as:

- anatomical structure;
- artery;
- tract;
- nucleus;
- named pathway;
- other explicit named entity already present in the current concept inventory.

Examples:

```text
Superior cerebellar artery
Corpos Striatum
Medial Lemniscus Tract
Anterior Corticospinal Tract
```

These are different from questions whose intended target is inherently:

- a function;
- a process;
- a relationship;
- a general property.

Do not force all educational questions to have named-entity answers.

The stronger target-answer rule applies when the selected concept itself is a named entity.

---

# 7. Generation Contract

For a named-entity target, the generation prompt must explicitly communicate:

```text
TARGET CONCEPT = X
```

and require that:

> The correct answer must identify TARGET CONCEPT X itself, or an explicitly supported equivalent representation of X.

It must explicitly prohibit answers that merely describe:

- the function of X;
- an effect caused by X;
- a property of X;
- a related structure;
- a neighboring anatomical entity;
- a broader system containing X.

Example:

```text
Target:
Corpos Striatum
```

Allowed:

```text
Corpos Striatum
```

Not sufficient:

```text
facilitates coordinated movement
```

Not sufficient:

```text
involved in planned motor movement
```

Not sufficient:

```text
basal ganglia
```

unless the existing concept identity system explicitly establishes that representation as the same target.

---

# 8. Preserve Educational Diversity

Do NOT reduce all questions to trivial:

```text
What is X?
```

The generated question may still test:

- anatomical role;
- location;
- connections;
- distinguishing characteristics;
- clinical relevance;
- relationships;

provided that the answer identifies the selected target.

For example:

```text
Which tract carries ...
```

may be an excellent question if the answer is:

```text
Medial Lemniscus Tract
```

The objective is not to make questions simpler.

The objective is:

> The question may test different properties of the concept, but the correct answer must identify the selected concept when the target is a named entity.

---

# 9. Important Distinction

The following are different:

### Question about a concept

```text
What function does the Corpos Striatum perform?
```

Answer:

```text
coordinates planned movement
```

### Question targeting the concept

```text
Which basal-ganglia structure is involved in executing planned motor movements?
```

Answer:

```text
Corpos Striatum
```

WP-040 must favor the second form when:

```text
selected target = Corpos Striatum
```

The first form is not necessarily medically incorrect; it is simply misaligned with the deterministic target-selection architecture.

---

# 10. Evidence Anchoring Must Remain

Do not weaken WP-037's concept anchoring.

The generation prompt must continue receiving the concept-specific evidence already selected by the planner.

The intended pipeline is:

```text
Selected concept
      +
concept-anchored evidence
      +
target-aware generation instructions
      ↓
target-aligned question
```

Do not replace targeted evidence with broader evidence.

Do not widen retrieval.

---

# 11. No Semantic Matching

Do NOT solve target alignment by introducing:

- embeddings;
- vector search;
- semantic similarity;
- LLM judges;
- fuzzy matching;
- external terminology databases.

The generated answer should align with the target because the generation contract explicitly requires it.

---

WP-038 ConceptIdentity and coverage matching remain unchanged.

WP-039 extraction/truncation recovery remains unchanged.

The purpose of WP-040 is to reduce the number of cases in which coverage has to interpret an answer that does not explicitly identify the selected concept.

```text

```

```text

```

# 15. Prompt Design

Inspect the existing generation prompt carefully.

Make the smallest change that creates an explicit target-answer contract.

The prompt should distinguish:

### Target

What concept must be tested?

### Evidence

What evidence should be used?

### Answer requirement

What must the correct answer identify?

For named concepts, the prompt should communicate a relationship equivalent to:

```text
The question must test TARGET CONCEPT.

The correct answer must identify TARGET CONCEPT itself.

Do not answer with merely its function, property, consequence,
related structure, broader category, or neighboring concept.
```

Use the project's existing terminology and prompt structure.

Do not create an unnecessarily large prompt rewrite.

---

# 16. Consider Answer Language

WP-038 demonstrated that the model may answer in Hebrew when the target concept is represented in English.

Do NOT solve that problem in WP-040 with fuzzy cross-language coverage.

However, investigate whether the generation prompt can safely say:

> If the target concept has an explicitly provided language representation in the generation context, use that representation in the correct answer.

Do not invent translations.

Do not create a bilingual dictionary.

Do not require English if the evidence/question is in Hebrew.

The key requirement is identity of the target, not a particular language.

---

# 17. Existing Candidate Model

Inspect:

```text
GeneratedQuestionResponse
CandidateQuestion
```

and determine whether the selected target is already available at the point where the candidate is constructed.

Prefer passing target information through the existing internal generation context rather than changing the public candidate schema.

Do not add redundant public fields.

---

# 18. Tests

Add tests at the generation-prompt/contract level.

### Named target

Given:

```text
Corpos Striatum
```

verify that the generated prompt explicitly requires the answer to identify the target.

### Functional answer prohibition

Verify that the prompt explicitly excludes:

```text
function-only answer
```

when the target is a named entity.

### Related entity

Verify that the target cannot be silently replaced by:

```text
broader system
related structure
neighboring structure
```

### Language

Verify that the target-answer requirement does not incorrectly require a language that is not supported by the evidence.

### Existing generation behavior

Verify that non-named target behavior is not unnecessarily changed.

---

# 19. Prompt Tests Must Be Meaningful

Do not merely test:

```text
"TARGET CONCEPT" in prompt
```

unless that is genuinely sufficient.

Tests should verify the semantic contract expressed by the prompt, including:

- target identification;
- correct-answer requirement;
- prohibition of function-only answers;
- preservation of evidence anchoring.

Keep tests robust against harmless wording changes where possible.
