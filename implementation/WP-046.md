WP-046 — Generalization Study of Evidence-Supported Ambiguity

1. Objective

WP-045 analyzed two concrete failures:

Globus Pallidus
Corticospinal Tract

It established that they do not share one safely identifiable pre-generation cause.

WP-045 also showed that a seemingly promising has_named_child rule creates a false positive and therefore must not be implemented without broader evidence.

WP-046 is therefore a diagnostic/generalization work package first, and an implementation work package only if the evidence justifies implementation.

The objective is:

Determine whether the ambiguity mechanisms observed in WP-045 generalize across the existing three pilot categories, and determine whether one or more deterministic structural mechanisms can safely address them.

The three categories are:

2. Architectural Principle

Do not generalize from two examples.

Do not generalize from terminology alone.

Do not create a rule merely because it correctly identifies known failures.

A proposed mechanism must be tested against:

problematic examples
+
successful controls
+
false-positive controls

before it is considered safe for production.

6. Build an Ambiguity Case Set

Inspect the available concepts and evidence in the three categories and construct a deliberate case set.

The case set must contain, where available:

A. Known failures

Globus Pallidus
Corticospinal Tract

B. Successful controls

Targets that have successfully generated accepted questions in the same or closely related evidence context.

Include successful siblings of problematic targets where available.

C. Parent/child candidates

Cases where the source evidence indicates:

parent
    ↓
child

D. Sibling/classification candidates

Cases where multiple concepts share a common classification or supported property.

E. Textual-containment cases

Cases where one concept string contains another, including cases that are NOT true semantic parent/child relationships.

The PICA case from WP-045 is a mandatory false-positive control.

F. Normal controls

Targets with no apparent ambiguity structure.

13. Textual Containment Investigation

Specifically test cases where:

A contains B

and determine whether:

A and B are the same real-world concept

or:

A and B are unrelated concepts

or:

A is genuinely a parent/child relationship

This is required because WP-045 demonstrated that textual containment alone is unsafe.

14. Classification Ambiguity Investigation

Identify cases where evidence supports:

A is X
B is X
C is X

and a generic question such as:

Which structure is X?

would have multiple valid answers.

Determine whether the application can identify this structure deterministically.

Do not use an LLM to classify the evidence.

15. Distinguish Three Levels

For every case, distinguish:

Level 1 — Evidence relationship

What does the source actually say?

Level 2 — Candidate relationship

How are the target and candidate related?

Level 3 — Question ambiguity

Does the generated question make both target and candidate correct?

This distinction is mandatory.

A parent/child relationship alone does not necessarily make a question invalid.

It becomes problematic only if the question's evidence-supported predicate applies to both.

17. Generalization Test

For every proposed pattern ask:

Does it explain more than one problematic case?

Then:

Does it correctly leave successful cases alone?

Then:

Does it avoid the PICA false positive?

A pattern that fails any of these tests must NOT be implemented.

19. No Production Implementation Yet

WP-046 remains diagnostic until the generalization analysis is complete.

Only if a deterministic mechanism satisfies the safety criteria below may Claude implement it.

20. Safety Criteria for Implementation

A proposed rule may be implemented only if:

it explains multiple real cases or one clearly general structural class;

it has successful controls;

it does not depend on target-specific names;

it does not depend on one exact phrase;

it does not use fuzzy matching;

it does not rely on LLM judgment;

it does not create the known PICA-style false positive;

it preserves existing validators;

it preserves the three-attempt budget;

it is deterministic and testable.

If these conditions are not met:

Do not implement the rule.

A negative result is acceptable.

31. Final Instruction to Claude

Do not start by implementing a distractor detector.

WP-046 is first a generalization study.

The two examples from WP-045 are hypotheses/examples, not sufficient evidence for a general production mechanism.

Use the three existing pilot categories as the controlled dataset.

The desired outcome is one of:

1. A safe general deterministic mechanism is demonstrated.
2. A narrower mechanism is demonstrated for a well-defined structural class.
3. No safe deterministic mechanism is demonstrated.

All three outcomes are acceptable.

The unacceptable outcome is:

implement a heuristic that works for
Globus Pallidus and Corticospinal Tract
but has not been tested against successful controls
and known false positives.

The architecture must prefer:

general evidence
over
special cases

and:

safe rejection
over
incorrect medical questions.
