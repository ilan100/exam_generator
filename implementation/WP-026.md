WP-001 through WP-025 are complete.

WP-025 successfully solved the within-category diversity problem by introducing
evidence-grounded QuestionTarget planning before generation.

The WP-025 acceptance run produced:

    40 planned
    36 accepted
    4 exhausted

and all 16 category pairs for which both questions were produced were judged
DISTINCT.

A focused read-only diagnostic then examined the four exhausted targets and
all 12 failed attempts.

The diagnostic found:

- grounding passed 12/12 attempts;
- category validation passed 12/12;
- textbook never blocked;
- MCQ failed 11/12;
- all four targets were classification/enumeration-shaped;
- ambiguity came primarily from multiple defensible answer choices;
- successful sibling targets generally asked about one specific item through
  one distinguishing property.

A controlled rerun reused the EXACT SAME four QuestionTargets without
replanning:

    חומר לבן                    accepted attempt 1
    היסטולוגיה                  accepted attempt 1
    המוח הקטן                   accepted attempt 3
    מערכת העצבים ההיקפית        exhausted again

The three successful recoveries did not require different factual targets.

They succeeded when generation framed the target as a question about one
specific distinguishing property rather than asking the student to recall the
entire enumeration.

Therefore the primary problem is not target factual validity or diversity.

It is the transformation:

    QuestionTarget
        ↓
    one-best-answer MCQ

WP-026 improves that transformation.

---

# 1. Objective

Improve target-constrained generation so evidence-grounded QuestionTargets,
especially classification/enumeration-shaped targets, are converted into
clear one-best-answer MCQs more reliably.

Preserve:

    planned factual target
    +
    planned diversity
    +
    factual evidence

while improving:

    MCQ framing
    distractor separability
    single-best-answer clarity

The intended flow remains:

    evidence
        ↓
    QuestionTargetPlanner
        ↓
    fixed QuestionTarget
        ↓
    target-aware MCQ generation
        ↓
    existing independent validators
        ↓
    existing bounded production attempts

Do NOT solve this by increasing retry counts.

Do NOT solve this by weakening MCQ validation.

Do NOT routinely re-plan targets after generation failure.

---

# 2. Core Generation Principle

Generation must distinguish between:

    factual target

and:

    literal question form

A QuestionTarget describes WHAT knowledge should be tested.

It does not require the generated MCQ to ask the factual_focus verbatim.

Example target:

    White matter consists of:
    - projection fibers
    - commissural fibers
    - association fibers

BAD interpretation:

    Which answer lists the types of white matter?

This encourages answer choices containing overlapping combinations of real
fiber types.

GOOD interpretation:

    Select one evidence-supported member/property relationship from the
    assigned target and ask a one-best-answer question about that
    distinguishing property.

For example:

    Which type of white-matter fiber connects cortical regions
    within the same hemisphere?

The generated question still tests the assigned target.

It has not switched to an unrelated fact.

---

# 3. Preserve Target Fidelity

Do NOT relax WP-025's target constraint.

Generation must still:

- remain within the assigned target;
- use the target's factual scope;
- use supplied factual evidence;
- not silently switch to another easier topic;
- not replace the target with another planned target;
- not broaden into unrelated category material.

However, generation MAY select a narrower testable relationship contained
within the assigned target when necessary to create a clean MCQ.

This distinction is critical:

    narrowing within target = allowed

    switching target = forbidden

Example:

Target:

    cerebellar nuclei include Fastigial, Interposed, Dentate

Allowed:

    Which cerebellar nucleus is associated in the supplied evidence with
    property X?

Not allowed:

    Ask about cerebellar motor learning merely because it is easier,
    unless that knowledge is actually part of the assigned target.

---

# 4. Enumeration / Classification Detection

Before modifying architecture, inspect the existing QuestionTarget model and
generation prompt.

Use the smallest reasonable implementation.

The generator should recognize targets whose factual focus contains patterns
such as:

- X consists of A/B/C;
- X is divided into A/B;
- X includes A/B/C;
- N layers/types/components;
- a list of structures;
- a classification hierarchy.

Prefer prompt-level semantic instruction over introducing a complicated
rule engine.

Do NOT build a general NLP classification framework unless clearly required.

The LLM is already capable of understanding whether a target contains
multiple listed/classified items.

The diagnostic demonstrated this capability indirectly: the same targets
sometimes generated good single-property questions spontaneously.

WP-026 should make that behavior intentional and reliable.

---

# 5. MCQ Framing Rules

Strengthen the generation instructions with explicit target-aware framing.

When the target contains multiple items, classifications, layers, structures,
or components:

PREFER questions that test:

- one member through one distinguishing property;
- one member through one function;
- one member through one location;
- one member through one relationship;
- one member through one alternate name;
- one classification level through an explicit distinguishing criterion;
- another similarly specific relationship supported by the supplied evidence.

AVOID asking directly for:

- the complete list;
- the complete enumeration;
- arbitrary combinations of members;
- "which of the following contains all correct components?";
- multiple facts bundled into one answer;
- one answer containing several independently-testable claims.

The goal is:

    one question
        ↓
    one discriminating fact
        ↓
    one clearly best answer

---

# 6. Distractor Construction

The diagnostic showed that ambiguity often came from distractors that were
real, evidence-adjacent classifications or combinations of true items.

Generation instructions should explicitly require distractors to be:

    plausible
    but
    clearly incorrect for the EXACT relationship being tested

Do not create distractors merely by rearranging or partially recombining true
members of the target enumeration.

Example:

If the target contains:

    projection
    commissural
    association

and the question tests:

    connects regions within the same hemisphere

then the distractors may include other relevant fiber types because the
question's distinguishing property makes only one correct.

But avoid answer choices such as:

    projection + commissural
    commissural + association
    projection + association

when the question asks broadly about "types of white matter."

---

# 7. Hierarchical Classification Ambiguity

The diagnostic found one especially reproducible failure:

    מערכת העצבים ההיקפית

Target:

    PNS
        ↓
    autonomic + somatic

The evidence also contains:

    autonomic
        ↓
    sympathetic + parasympathetic

Across two independent runs, all six attempts produced ambiguity involving
the adjacent hierarchy.

Handle this explicitly at generation time.

When the evidence contains nested classifications:

    parent
        ↓
    children
        ↓
    grandchildren

the generated question must make the hierarchy level explicit.

For example, distinguish clearly between:

    main divisions of the PNS

and:

    divisions of the autonomic nervous system

Do not use a true classification from another hierarchical level as a
plausibly-correct distractor unless the wording makes it unquestionably
incorrect.

This is a GENERAL rule.

Do NOT special-case:

    מערכת העצבים ההיקפית

or any category name.

# 8. Planner Changes — Only If Necessary

The diagnostic classified the architectural issue as a narrowly scoped
target-planning quality issue, but recommended generation improvement as the
primary intervention.

Therefore:

FIRST attempt to solve the observed problem through target-aware generation.

Do not substantially redesign QuestionTargetPlanner.

A small planner-prompt clarification MAY be added only if necessary:

    Prefer targets that can support a clear one-best-answer MCQ while
    preserving factual diversity.

But do NOT:

- reject all enumeration targets;
- prohibit classification targets;
- add a second planner LLM call;
- add target re-planning after generation failure;
- reduce diversity merely to choose easier questions.

Enumeration targets can contain excellent exam material.

The control run demonstrated that 3 of the 4 previously failed targets could
produce valid MCQs without replanning.

If a planner change is made, document exactly why generation-only guidance was
insufficient.
