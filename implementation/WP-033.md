# WP-033 — Category Question Set API

## Context

Read completely:

WP-032 established the project's new primary abstraction:

Generate Next Question For Category.

WP-033 establishes the permanent request/response contract for this capability.

This is an architectural work package.

Generation behavior should remain unchanged.

No prompt tuning.

No diversity improvements.

No planner improvements.

No validation changes.

---

# 1. Objective

Replace the current category-generation request with a permanent "Category Question Set" contract.

The application no longer receives only a category.

It receives:

- the category
- the questions already belonging to this category
- generation options

The generator extends that question set by exactly one question.

---

# 2. New Request Model

Create a new immutable request model.

Example:

```json
{
    "category": "...",

    "existing_questions": [
        ...
    ],

    "generation_options": {
        "difficulty": "auto",
        "style": "auto"
    }
}
```

existing_questions may contain:

- 0 questions
- 1 question
- 2 questions
- 3 questions

All four cases are valid.

No assumptions may be made about the count.

---

# 3. Existing Question Contract

Every existing question uses exactly the production JSON schema.

Do not introduce a lightweight version.

Do not create duplicate models.

Reuse the production question model.

Every field must be preserved, even if currently unused.

Future work packages may begin using additional fields.

---

# 4. New Question Contract

The generated question must use exactly the same schema as every existing question.

There must not be two different representations.

Generation should return one additional production question.

The orchestration layer remains responsible for assigning runtime identifiers such as:

- number
- id

if they are not already available.

Generation is responsible only for the question content.

---

# 5. Service Responsibility

CategoryGenerationService now becomes:

CategoryQuestionSetService

Its responsibility becomes:

Receive a category question set.

Return one additional question.

Nothing more.

---

# 6. Internal Pipeline

Initially:

Pass existing_questions through unchanged.

Do NOT yet:

- summarize them
- extract concepts
- compute diversity
- compute coverage
- compute relationships

Those belong to later work packages.

WP-033 changes the contract only.

---

# 7. Backward Compatibility

The previous request model should remain temporarily supported internally.

The CLI should transparently build the new request model.

Existing behavior must remain unchanged.

---

# 8. Tests

Add tests covering:

- empty question set
- one existing question
- two existing questions
- three existing questions

Verify identical request validation.

Verify generated question uses the production schema.

Verify backward compatibility.

Regression suite must pass.

---

# 10. Acceptance Criteria

Success means:

- identical generation quality
- identical validation

- identical output schema

while successfully replacing the request contract.
