WP-038 identified and isolated a new coverage failure mode:

A concept extracted from the evidence can itself be incomplete/truncated.

Examples observed in the real pilot:

```text
Anterior Corticospinal T
```

instead of:

```text
Anterior Corticospinal Tract
```

and:

```text
Corpos Str
```

instead of:

```text
Corpus Striatum
```

The generation system can correctly generate a question about the complete concept, but the planner later compares the generated answer against the incomplete stored concept and fails to recognize that the concept was already tested.

This creates:

```text
Truncated concept extraction
        ↓
Correct question generation
        ↓
Complete generated answer
        ↓
Coverage mismatch
        ↓
Same concept selected again
        ↓
Repeated generation
        ↓
Possible exhaustion
```

WP-038 also established that broad cross-language matching should NOT be pursued under the current architecture.

WP-039 therefore focuses exclusively on **deterministic trailing-truncation recovery at concept extraction time**.

---

# 1. Objective

Improve deterministic concept extraction so that clearly incomplete trailing fragments are either:

1. deterministically reconstructed to the complete concept, or
2. excluded from the concept inventory when safe reconstruction is impossible.

The objective is NOT general spelling correction.

The objective is NOT fuzzy matching.

The objective is NOT semantic matching.

The objective is:

> Prevent obviously incomplete concept identities from entering the planner when their complete form can be established deterministically from the supplied evidence.

---

# 2. Core Architectural Principle

The ownership must remain:

```text
Evidence
    ↓
Concept Extraction
    ↓
Concept Quality / Completeness
    ↓
Concept Identity
    ↓
Coverage
```

Do NOT solve this in the coverage layer.

Do NOT make coverage more permissive to compensate for malformed concepts.

A malformed concept should be corrected or rejected before it becomes a planning target.

---

# 3. Scope

The pilot remains limited to the same three categories:

- אספקת דם
- מסילות עצביות
- גרעיני הבסיס

Do not expand the deterministic concept system to all categories in this WP.

---

# 4. Investigate the Existing Extraction Pipeline First

Before changing code:

1. Locate the current concept extraction implementation.
2. Identify exactly how `InventoryConcept` text is produced.
3. Inspect the evidence chunks from which the observed truncations originated.
4. Determine whether the complete concept exists elsewhere in the same evidence.
5. Determine whether the truncation is caused by:
   - extraction boundary;
   - line parsing;
   - heading parsing;
   - PDF text extraction;
   - chunking;
   - punctuation;
   - another deterministic preprocessing behavior.

Do not assume the cause.

Document the actual cause found in the code/evidence.

---

# 5. Real Cases Must Be Reproduced

Create tests based on the actual observed forms:

```text
Anterior Corticospinal T
```

and:

```text
Corpos Str
```

The tests must reproduce the structural conditions under which these malformed concepts were extracted.

Do not merely add tests that call a repair function with two strings.

The goal is to test the actual extraction path.

---

# 6. Define "Trailing Truncation"

Before implementation, define a deterministic condition for a suspicious trailing truncation.

The definition must be based on observable structure.

Potential signals may include:

- concept ends in an incomplete word fragment;
- the source evidence contains a longer matching form;
- the longer form occurs in the same relevant evidence context;
- the longer form can be identified without semantic inference.

The exact rule must be derived from the actual corpus and implementation.

Do not invent a generic heuristic simply because it works on the two examples.

---

# 7. Deterministic Reconstruction

A reconstruction is allowed only when the complete concept can be established unambiguously from available evidence.

For example, if the same evidence contains:

```text
Anterior Corticospinal T
...
Anterior Corticospinal Tract
```

then reconstruction may be safe if the implementation can deterministically establish that these are the same extracted concept.

Likewise, if the relevant evidence unambiguously contains:

```text
Corpus Striatum
```

and the malformed inventory fragment is:

```text
Corpos Str
```

the implementation may repair it only if the relationship is structurally provable.

Do NOT use:

- LLMs;
- embeddings;
- semantic similarity;
- fuzzy matching;
- edit distance as a general repair mechanism;
- external terminology databases;
- manually authored concept mappings.

---

# 8. Important: Do Not Assume Prefix Matching Is Safe

Do not simply implement:

```text
if long_form.startswith(short_form):
    repair
```

This is insufficient.

The real observed case:

```text
Corpos Str
```

does not equal a clean prefix of:

```text
Corpus Striatum
```

Therefore the repair mechanism must be based on the actual evidence structure, not merely string-prefix completion.

If a safe deterministic mechanism cannot handle a case, exclude the concept rather than guess.

---

# 9. Candidate Sources for Reconstruction

Investigate, in this order:

### A. Same evidence chunk

Can the complete form be deterministically recovered from the same source chunk?

### B. Same source page / source unit

If the chunk is insufficient, can the same source page provide an unambiguous complete form?

### C. Other evidence chunks from the same category

Only consider this if there is a clear deterministic relationship established by the existing evidence structure.

Do not use global corpus search as a semantic lookup.

Do not select the most similar-looking term.

If multiple plausible candidates exist, the result is ambiguous.

Exclude the malformed concept.

---

# 10. Ambiguity Rule

This is mandatory.

If more than one plausible reconstruction exists:

```text
DO NOT REPAIR
```

Instead:

```text
EXCLUDE CONCEPT FROM INVENTORY
```

The system must prefer:

```text
missing concept
```

over:

```text
wrong concept
```

---

# 11. No General Text Correction

WP-039 must not become:

```text
spell checker
```

Do not attempt to fix:

- arbitrary spelling errors;
- OCR errors generally;
- grammatical errors;
- transliteration inconsistencies;
- Hebrew/English translations;
- arbitrary abbreviations;
- semantic synonyms.

The scope is specifically:

> structurally identifiable incomplete/truncated concept extraction.

---

# 12. Preserve Canonical Evidence Provenance

If a concept is reconstructed:

- preserve the original canonical `chunk_id`;
- do not invent a new evidence ID;
- do not alter the source evidence;
- retain enough information to explain why the reconstruction was considered deterministic.

If a concept is excluded:

- do not create a fake replacement concept.

---

# 22. Primary Success Criterion

The primary objective is:

> Eliminate repeated selection caused specifically by malformed trailing-truncated concept identities, without introducing false repairs.

For the known cases, we want to prevent:

```text
Anterior Corticospinal T
        ↓
generated answer: Anterior Corticospinal Tract
        ↓

        ↓
```


# 25. Failure Interpretation

### Outcome A — Successful repair

Known truncation cases are deterministically repaired.

Repeated selection disappears.

Alignment remains high.

No false repairs.

→ Strong success.

### Outcome B — Some truncations repairable

Some cases can be reconstructed safely; others cannot.

→ Keep only safe repairs and exclude ambiguous cases.

### Outcome C — Reconstruction cannot be made safe

→ Do not guess.

→ Exclude malformed concepts.

→ Document the limitation.

### Outcome D — False repair observed

→ Stop.

A false concept repair is more serious than leaving the concept unavailable.
