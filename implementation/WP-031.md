WP-029 established that distractor synthesis is now the dominant remaining architectural bottleneck.

WP-030 introduced deterministic relationship modelling.

Its evaluation showed that relationship awareness alone is insufficient to eliminate multiple-supported-answer failures.

WP-031 implements the second architectural layer:

Competitor Discovery.

---

# 1. Objective

Introduce deterministic competitor discovery.

The application should identify concepts that are plausible competitors for the tested concept before generation.

The application does NOT generate distractors.

It only determines the candidate competitor set.

---

# 2. Architectural Principles

The application owns:

- competitor discovery
- competitor ranking
- filtering

The LLM owns:

- expressing the final MCQ

Maintain this separation.

---

# 3. Competitor Model

Introduce an immutable model:

CompetitorCandidate

containing only information genuinely known before generation.

Possible fields:

- concept
- source evidence
- relationship relevance
- similarity reason

Do NOT include generation decisions.

Do NOT include distractor text.

---

# 4. Competitor Discovery

Implement deterministic competitor discovery.

Allowed information:

- retrieved evidence
- category
- relationship
- factual focus

No additional retrieval.

No LLM calls.

No embeddings.

No vector database.

No ontology.

Use only information already present in the current pipeline.

---

# 5. Ranking

Rank discovered competitors.

Ranking should be deterministic.

Document the ranking policy.

Do not tune it using evaluation results.

---

# 6. Prompt Integration

Generation prompt now receives:

- correct concept
- tested relationship
- competitor list
- evidence

The prompt must clearly distinguish:

Correct concept

vs.

Possible competing concepts

Do not instruct the model which competitors to use.

---

# 7. Scope Boundary

Generation still chooses:

- distractors
- wording
- final answer ordering

The application only constrains the search space.

---

# 8. Validation

No validator changes.

No acceptance changes.

No retry changes.

No grounding changes.

---

# 9. Diversity

Do not modify planner diversity.

Do not introduce competitor diversity scoring.

Only provide richer inputs to generation.

---

# 10. Tests

Add tests covering:

- deterministic competitor discovery
- ranking stability
- immutability
- prompt rendering
- backward compatibility
- zero additional LLM calls
- zero additional retrieval

Regression suite must pass.

---

# 11. Focused Evaluation

Repeat WP-030's focused evaluation methodology.

- מערכת העצבים ההיקפית
- אספקת דם
- תאי מערכת העצבים

Measure:

- grounding failures
- "another answer also supported"

- average attempts

Compare against:

- WP-027
- WP-028
- WP-030

No prompt tuning after results.

---

# 12. Full Acceptance Run

Run exactly once.

20 categories.

2 questions each.

WP-023 partial exam behavior remains active.

No reruns.

---

# 13. Success Criteria

Primary metric:

Reduction in grounding failures caused by:

"another answer also supported"

Secondary metrics:

- acceptance rate
- average attempts
- first-pass acceptance

Quality must never decrease.

---

# 14. Architectural Evaluation

Explicitly answer:

Did deterministic competitor discovery improve generation quality?

If not,

explain why,

using evidence rather than speculation.

---

# 15. Scope Exclusions

- implement distractor synthesis
- implement archetype selection
- add embeddings
- add vector databases
- redesign retrieval
- redesign validators
- redesign QuestionTarget
- redesign QuestionRelationship
- add another planner

Competitor discovery only.
