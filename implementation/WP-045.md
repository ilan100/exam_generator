# WP-045 — Deterministic Detection of Evidence-Supported Question Ambiguity

## 1. Objective

WP-044 validated the structural-generation-constraint approach.

The live acceptance trend is:

```text
WP-040: 11/12 accepted
WP-041:  9/12 accepted
WP-043:  5/12 accepted
WP-044:  8/12 accepted
```

WP-044 demonstrated two important successes:

1. `Corpos Striatum` was safely skipped because its evidence was recognized as an unsafe enumeration shape.
2. `Basillar artery` successfully generated source/origin questions after its concrete source relationship was exposed to generation.

However, two targets repeatedly failed:

```text
Globus Pallidus
Corticospinal Tract
```

Their generated questions were rejected because multiple answer choices were supported by the supplied evidence.

The central objective of WP-045 is:

> Determine why evidence-supported questions are sometimes not uniquely answerable, and determine whether this can be prevented using a narrow, deterministic, structural constraint before generation.

---

## 2. Critical Principle

Do **not** assume that `Globus Pallidus` and `Corticospinal Tract` have the same underlying cause.

WP-044 identified several possible ambiguity shapes:

```text
A. Enumeration ambiguity

B. Classification ambiguity

C. Parent/child hierarchy ambiguity
```

WP-045 must determine which of these actually explains each failure.

The first phase is therefore **diagnosis**, not coding.

## 9. Evidence Ambiguity vs Question Ambiguity

Determine whether the problem is:

### Evidence problem

The evidence itself does not uniquely distinguish the target.

### Question-generation problem

The evidence contains target-distinguishing information, but the LLM chooses a question form that throws that information away.

Example:

```text
Evidence:
A
B
C

plus a unique property of B
```

Bad:

```text
Which of the following is part of X?
```

Potentially valid:

```text
Which structure has <target-specific property supported by evidence>?
```

If the latter is possible, the problem is primarily a generation constraint.

If no target-specific information exists, the correct action may be:

```text
skip
```

---

## 10. Determine Whether a Safe Question Exists

For each target explicitly answer:

> Does the authoritative evidence contain enough information to construct a question for which the selected target is uniquely correct?

Use only existing source evidence.

Do not add medical knowledge.

For diagnosis classify:

```text
UNIQUE_QUESTION_SUPPORTED
```

or:

```text
NO_UNIQUE_QUESTION_SUPPORTED
```

Do not automatically make this a production field yet.

---

## 11. Investigate the Shared-Predicate Pattern

Investigate whether the following structure exists:

```text
Target A
Target B
Target C
```

all occurring under a common predicate such as:

```text
is a motor tract
is part of basal nuclei
is supplied by artery X
```

If a generated question tests only the common predicate, multiple entities may be correct.

Determine whether the application can detect this structurally.

Potential signals include:

```text
multiple named concepts
+
same local evidence block
+
same predicate/context
```

Do not implement this until it is confirmed against the real failures.

---

## 12. Investigate Local Sibling Structure

Inspect the local evidence around each target.

Determine whether it has a structure like:

```text
Target
Sibling
Sibling
Sibling
```

sharing the same immediate evidence context.

For example:

```text
Basal nuclei:
    Caudate Nucleus
    Putamen
    Globus Pallidus
```

If so, determine whether a generic membership question would necessarily have multiple valid answers.

This may provide a deterministic signal broader than WP-044's explicit enumeration cue phrases.

---

## 13. Investigate Parent/Child Structure Separately

For:

```text
Globus Pallidus
Globus Pallidus Internus
```

determine from the actual evidence whether the relationship is:

```text
parent
  ↓
child
```

or simply sibling concepts sharing a textual context.

Do not infer hierarchy from names alone.

Use the actual source evidence.

---

## 14. Do Not Blindly Expand the Enumeration Detector

WP-044 deliberately used narrow cue phrases.

Do not simply add many new phrases until the detector catches everything.

That would turn:

```text
deterministic narrow rule
```

into:

```text
large heuristic classifier
```

Instead determine the actual structural property first.

---

## 15. Phase 2 — Architectural Decision

Only after diagnosis decide whether production code should change.

There are three acceptable outcomes.

### Outcome A — One common deterministic pattern

If both targets share a safe structural pattern:

```text
implement one narrow deterministic constraint
```

### Outcome B — Two different patterns

If the targets fail differently:

```text
implement only the smaller necessary fixes
```

### Outcome C — No safe deterministic signal

If the evidence does not support a reliable deterministic rule:

```text
do not implement speculative heuristics
```

Document the limitation and recommend the next architectural step.

---

## 16. Preferred Architectural Principle

The application should determine:

```text
whether the evidence can uniquely support the target
```

The LLM should determine:

```text
how to phrase the question
```

The validator should determine:

```text
whether the generated question actually satisfies the contract
```

Desired separation:

```text
Python
  ↓
structural constraints
  ↓
LLM
  ↓
candidate question
  ↓
deterministic validation
```

---

## 17. If a Deterministic Ambiguity Signal Is Found

Prefer a pre-generation mechanism:

```text
Target
  ↓
Evidence analysis
  ↓
Potential ambiguity detected
  │
  ├── target uniquely distinguishable
  │      ↓
  │   generation allowed
  │
  └── target not uniquely distinguishable
         ↓
       skip target
```

Do not generate merely because a target has evidence.

---

## 18. If Target-Specific Evidence Exists

If evidence contains:

```text
target:
    B

common context:
    A, B, C

target-specific evidence:
    B has property P
```

generation should be constrained to test property P rather than generic membership.

The property must come from authoritative evidence.

Do not invent it.

Do not hard-code exact question wording.

---

## 19. If Target-Specific Evidence Does Not Exist

If evidence only establishes:

```text
A
B
C
```

as members of a category and contains no target-specific distinguishing information:

```text
skip
```

This follows:

> **Prefer missing over wrong.**

Do not force a question.

---
