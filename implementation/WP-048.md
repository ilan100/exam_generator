# WP-048 — Classification Ambiguity Investigation

## 1. Objective

WP-047 resolved the target-to-answer identity problem for the current named-entity pilot scope.

The primary remaining architectural problem is now:

```text
generic classification ambiguity
```

The current evidence includes real failures involving:

```text
Globus Pallidus
Caudate Nucleus
Nucleus Accumbens
Basillar artery
```

The failure pattern is broadly:

```text
target
    ↓
LLM generates a generic classification question
    ↓
more than one answer choice satisfies the question predicate
    ↓
grounding and/or MCQ validation rejects the candidate
```

WP-048 must determine whether these failures share a common structural cause and whether that cause can be detected deterministically and safely.

The goal is **not** to create special cases for the four targets.

The goal is:

> Determine whether a general, evidence-based, deterministic mechanism can identify questions whose predicate is satisfied by multiple candidate answers.

A negative result is acceptable.

# 6. First Principle

Do not begin by implementing a validator.

First establish:

```text
What exactly makes these questions ambiguous?
```

The central question is:

> Is the problem caused by the target/evidence itself, by the generated question predicate, by the answer-choice selection, or by an interaction among them?

Do not assume the answer.

---

# 7. Phase 1 — Reconstruct Every Known Failure

For every known classification-ambiguity failure, create a complete record.

Required fields:

```text

```

The analysis must distinguish:

```text
FACT
```

```text

```

and:

```text
HYPOTHESIS
```

---

# 8. Phase 2 — Identify the Actual Question Predicate

For every failure, explicitly state the predicate being tested.

For example, do not merely record:

```text
Which of the following is part of the basal nuclei?
```

Translate the operational meaning to:

```text
P(x) = x is a member of the basal nuclei
```

Then determine:

```text
P(correct_answer) = true
P(distractor_1) = ?
P(distractor_2) = ?
P(distractor_3) = ?
```

The key question is:

```text
How many answer choices satisfy P(x)?
```

If:

```text
count(P(x) == true) > 1
```

then the question is structurally ambiguous.

Do this analysis from the actual evidence available to the system.

---

# 9. Do Not Confuse Factual Truth With Question Validity

A question can be:

```text
factually true
```

and still be:

```text
invalid as an MCQ
```

Example:

```text
Which structure is part of category X?
```

If both:

```text
A
B
```

are members of category X, then:

```text
A is factually correct
```

does not make:

```text
A
```

a uniquely correct MCQ answer.

WP-048 must explicitly maintain this distinction.

The purpose is to determine whether ambiguity is tied to:

```text
target

```

or some combination.

# 13. Target Evidence Shape Investigation

Determine whether the target's available evidence is inherently prone to generic classification questions.

Examples to investigate:

```text
target is one member of a category

```

Test it against successful controls.

---

# 14. Question Predicate Investigation

Determine whether the LLM repeatedly chooses predicates of the form:

```text
"is a member of X"
"is part of X"
"belongs to X"
"is classified as X"
"participates in X"
```

or other generic predicates.

Do not restrict the investigation to these exact phrases.

Identify semantic equivalents from real data.

The important question is:

> Does the predicate describe the target uniquely, or does it describe a class containing multiple possible answer concepts?

---

# 15. Distractor Investigation

Inspect the actual distractors.

Determine:

```text
why each distractor was selected
whether each distractor is supported by evidence
whether each distractor satisfies the question predicate
whether the ambiguity could be detected without understanding the entire corpus
```

Do not assume the distractor generator is solely responsible.

---

# 16. Evidence Investigation

For each ambiguous question determine:

```text
Does the authoritative evidence support the correct answer?
Does the authoritative evidence support one or more distractors?
Does the evidence explicitly establish the same predicate for multiple concepts?
```

The student summaries remain the sole factual grounding authority.

The course book remains a secondary consistency check only.

Historical questions remain style/structure references only.

Do not use external medical knowledge to declare a distractor correct.

---

# 17. Candidate-Set Analysis

For every failure determine:

```text
candidate set
```

and:

```text
which candidates satisfy the predicate
```

Create a formal representation where possible:

```text
P(A) = true
P(B) = true
P(C) = false
P(D) = false
```

Then:

```text
unique correct answer = false
```

This is the core evidence needed for any potential deterministic mechanism.

---

# 18. Distinguish Two Different Failure Types

Do not merge:

### Type 1 — Multiple supported answers

```text
A and B are both supported by evidence
and both satisfy the question predicate.
```

### Type 2 — Factual disagreement

```text
A is supported
B is not supported
but the validator rejects for another reason.
```

Only Type 1 is the primary WP-048 target.

Record Type 2 separately.

# 20. Investigate Whether a Deterministic Signal Exists

Potential signals may include:

```text
multiple answer choices supported by the same evidence predicate
same category-membership relation for multiple candidates
duplicate predicate satisfaction
shared evidence statement
candidate concepts explicitly belonging to the same class
```

These are investigation hypotheses only.

Do not implement them until tested against controls.

---

# 21. False-Positive Requirement

For every candidate signal, find counterexamples.

A proposed rule must answer:

```text
When the rule fires,
does that always mean the generated question is actually ambiguous?
```

A rule that fires because:

```text
target has siblings
```

is insufficient.

A rule that fires because:

```text
multiple concepts exist in the same category
```

is insufficient.

The mechanism must be tied to the **actual generated question predicate and actual answer choices**.

---

# 29. Candidate Implementation Principle

If a safe deterministic signal is found, prefer:

```text
small post-generation deterministic check
```

following the established WP-046/WP-047 pattern.

It should:

- inspect the actual generated question;
- inspect the actual answer choices;
- use only deterministic information;
- reject only when multiple answers are demonstrably supported for the same predicate;
- use `InvalidGeneratedOutputError`;
- consume the existing attempt;
- make no additional LLM call.

Do not implement until the evidence supports it.

# 31. Safety Criteria for Implementation

A mechanism may be implemented only if all applicable criteria are satisfied:

1. explains multiple real failures or one clearly defined structural class;
2. has successful controls;
3. is tied to the actual generated predicate;
4. is tied to actual answer choices;
5. does not depend on target-specific names;
6. does not depend on exact wording;
7. does not use fuzzy semantic matching;
8. does not require an LLM judge;
9. does not require external medical knowledge;
10. preserves WP-044;
11. preserves WP-046;
12. preserves WP-047;
13. preserves the three-attempt budget;
14. is deterministic and testable;
15. has an explicit false-positive analysis.

If any critical criterion fails:

> Do not implement the mechanism.
