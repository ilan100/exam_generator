# WP-035 — Concept Ownership Investigation

## Context

Read completely:

- docs/MASTER_PROJECT_BRIEF.md
- docs/ARCHITECTURE.md
- docs/PROJECT_STATUS.md
- implementation/WP-034_COMPLETION_REPORT.md
- implementation/WP-034_ARCHITECTURE_REVIEW.md

WP-034 demonstrated that simply informing the planner about previous coverage does not reliably improve diversity.

The planner still repeatedly selects the strongest evidence.

Before implementing additional planning logic, we must determine whether concept selection itself should move from the LLM into deterministic application code.

This is an investigation work package.

It should not change production behavior.

No production code should be modified unless strictly required to perform measurements.

---

# 1. Objective

Answer one architectural question:

Can concept selection be owned by the application instead of the LLM?

Support the conclusion with evidence.

Not opinion.

---

# 2. Scope

Investigate only.

Do NOT improve generation.

Do NOT improve prompts.

Do NOT redesign validators.

Do NOT redesign retrieval.

Do NOT redesign competitors.

Do NOT redesign relationships.

Do NOT modify production planning.

---

# 3. Candidate Concept Study

Choose several representative categories.

Include at least:

- one content-rich category
- one weak category (for example מבוא)
- one category previously showing diversity problems

For each category:

Retrieve the production evidence exactly as production currently does.

Study the retrieved evidence.

Determine:

Can the important concepts be identified deterministically?

Document examples.
