# WP-050 — Generation Candidate Uniqueness Study

## 1. Objective

WP-048 established that the dominant classification-ambiguity problem is already detected by the existing validation layer.

WP-049 then tested a minimal prompt-based intervention.

The result was:

```text
INCONCLUSIVE
```

The most important learning from WP-049 is:

```text
more specific
    ≠
uniquely identifying
```

The generator can produce a question that tests a specific property and still select a property that is shared by multiple plausible answer concepts.

Example observed in WP-049:

```text
Target:
Caudate Nucleus

Generated predicate:
influences decision-making

Evidence:
Caudate Nucleus → supported
Nucleus Accumbens → also supported

Result:
ambiguous
```

WP-050 therefore investigates the deeper architectural question:

> **Can the existing candidate and evidence architecture provide structured information that allows generation to select a property that is true for the target and false for the plausible distractors?**

This is an **architectural investigation first**.

Do not implement a production mechanism unless the investigation establishes that a safe, general mechanism is justified.

# 8. Formal Target-vs-Candidate Model

For each candidate predicate `P`, represent:

```text
P(target) = true
```

and for each candidate distractor:

```text
P(distractor_i) = true / false / unknown
```

The desired uniqueness condition is:

```text
P(target) = true
```

and:

```text
P(distractor_i) = false
```

for every plausible distractor.

If:

```text
P(target) = true
P(distractor_i) = true
```

then the predicate is not uniquely identifying.

If:

```text
P(distractor_i) = unknown
```

do not silently treat it as false.

Unknown is a distinct state.
