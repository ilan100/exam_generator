# WP-058 — English-Only Generation Compliance

## 1. Objective

WP-057 successfully implemented the permanent narrow strategy:

```text
גרעיני הבסיס + Globus Pallidus
    → IDENTITY_FIRST
```

The strategy implementation passed the full regression suite and the real production-path verification.

However, the live WP-057 verification exposed a separate project-level compliance problem:

```text
Generated:
"איזה מהמבנים הבאים הוא Globus Pallidus?"
```

The project has an explicit language rule:

```text
If an English representation exists:
    use English.

Use Hebrew only when Hebrew is the only available representation.
```

Therefore the accepted WP-057 output was not compliant, even though its semantic identity framing and all existing validators passed.

WP-058 is therefore a **general language-compliance investigation and implementation task**.

The objective is:

> Determine where the English-first requirement currently exists, why the real generation pipeline can still produce Hebrew when an English representation exists, and implement the smallest general mechanism that reliably enforces the requirement.

This WP is **not** a Globus Pallidus-specific fix.

It is **not** an identity-first-specific fix.

It must establish English-first behavior as a reliable project-wide invariant wherever the rule applies.

---

# 2. Problem Statement

The current architecture can produce:

```text
Hebrew + English
```

even when:

```text
English representation exists
```

Observed example:

```text

```

```text
Which of the following is Globus Pallidus?
```

The important distinction is:

```text
semantic validity
    ≠
language-policy compliance
```

WP-058 must investigate and close this gap.

# 4. Critical Language Rule

This rule is NON-NEGOTIABLE:

```text
If an English representation exists:
    use English.

Use Hebrew only when Hebrew is the only available representation.
```

Interpretation:

### Case A — English exists

Use English.

Example:

```text
Globus Pallidus
Caudate Nucleus
Nucleus Accumbens
Which of the following is...
```

Do not use Hebrew merely because a Hebrew translation also exists.

### Case B — English does not exist

Hebrew may be used.

### Case C — Mixed-language output

Mixed Hebrew/English is not automatically acceptable.

If the Hebrew portion has an available English representation, English must be used.

---

# 5. Important Scope Clarification

WP-058 must not reinterpret the project rule as:

```text
prefer English when convenient
```

The rule is stronger:

```text
English exists
    →
Hebrew must not be used for that item.
```

The task is therefore to determine how to make this deterministic enough that an accepted output cannot violate the rule.

# 12. Important Distinction: Terminology vs Natural Language

```text

```

inside a Hebrew sentence.



