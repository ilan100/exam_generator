# WP-063 — First Post-WP-060 Deterministic Target-Planning Category Pilot

## 1. Objective

WP-060 established that the existing deterministic target-inventory mechanism is technically reusable beyond the current pilot categories. WP-061 and WP-062 aligned the language-policy architecture/runtime sufficiently for the project to continue, with documented enforcement limitations.

WP-063 is therefore the first controlled post-WP-060 deterministic target-planning category pilot.

The objective is NOT global rollout. It is:

```text
select ONE additional canonical category
        ↓
construct its deterministic target inventory
        ↓
integrate it into target planning
        ↓
run a controlled generation sample
        ↓
measure target alignment, grounding, reliability and cost
        ↓
compare with the current baseline
        ↓
STOP for architect review
```

This is an experiment, not a rollout.

---

## 2. Architectural Context


## 3. Critical Constraint

WP-063 MUST operate on exactly:

```text

```

Do not enable deterministic target planning for all remaining categories.

Do not add multiple categories to the production pilot.

Do not generalize the implementation before the experiment has produced evidence.

## 4. Category Selection

The category must be selected from the non-current deterministic-pilot categories identified by WP-060.

Evaluate at least:

```text
1. student-summary source structure quality
2. concept-inventory quality
3. target distinctiveness
4. deterministic-anchor quality
5. expected usefulness for target-specific questions
6. ability to validate target alignment objectively
7. category importance
8. experimental information value
9. low risk of category-specific special cases
```

Do not select merely by inventory size or alphabetical order.

Create:

```text
implementation/WP-063_CATEGORY_SELECTION.md
```

containing:

```text

deterministic feasibility
target quality
experimental value
risks

rejected alternatives
selection rationale
```

If two or more candidates are genuinely tied and the choice could materially affect the experiment:

```text
STOP
```

and request architect selection.

## 5. Existing Deterministic Mechanism


## 6. Source Authority

Target inventories must remain grounded in:

```text
student summaries
    = factual grounding authority
```

Preserve:

```text
course_book.pdf
    = secondary consistency check

historical Excel
    = style / structure / terminology reference
```

Do not use the course book or historical Excel as independent factual authority for target creation.

---

## 7. Inventory Construction

For the selected category:

```text
retrieve relevant student-summary evidence
        ↓
extract deterministic concept inventory
        ↓
refine/normalize with the existing mechanism
        ↓
inspect the resulting targets
```

Preserve source provenance, deterministic identifiers, category association and supporting evidence.

Do not invent unsupported concepts.

---

## 8. Inventory Quality

Inspect for:

```text
duplicates
truncation
generic concepts
non-anatomical noise
weak concepts
ambiguity
unsupported concepts
category leakage
poor anchors
```

Do not introduce fuzzy entity merging.

Prefer a smaller reliable inventory over a larger noisy one.

---

## 9. Target Anchoring


## 10. Target Diversity

Do not manually curate only easy targets for the generation experiment.

Use the existing target-selection mechanism so that the experiment reflects realistic system behavior.

The objective is to discover whether deterministic target planning improves generation across a representative sample.

## 11. Language Policy

All generated questions remain subject to:

```text
docs/LANGUAGE_POLICY.md
```

The authoritative rule is:

```text
Question prose:
    Hebrew

Professional/technical/terminological item:
    English whenever an established English representation exists

Hebrew:
    permitted only when no English representation exists

Whole-question English:
    NOT REQUIRED
```

Do not create a category-specific language policy.

Do not weaken the project-wide rule.

WP-062's partial deterministic enforcement does not weaken the policy itself.

## 18. Target Alignment

```text

```

```text

```

## 19. Target Drift

Explicitly inspect for:

```text
neighboring concept instead of target
broader category instead of target
target name present but question asks about another concept
factually correct but target-incoherent question
```

Target alignment is a central success criterion.

## 33. Decision Threshold

There is no simplistic rule such as:

```text
pass rate > X%
    → rollout
```

Evaluate together:

```text
target alignment
grounding quality
failure modes
generation reliability
cost
inventory quality
category characteristics
```

A high aggregate pass rate with severe target drift is not a success.

A lower pass rate with clearly correctable issues may still produce valuable architectural evidence.

---

```text
deterministic planning did not improve this category

```
