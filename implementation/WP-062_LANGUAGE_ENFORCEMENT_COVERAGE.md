# WP-062 — Language Enforcement Coverage

Authoritative policy: `docs/LANGUAGE_POLICY.md`.

This table describes actual implemented coverage after WP-062, not desired or aspirational coverage. "Runtime Enforcement" means a deterministic post-generation check in `src/exam_generator/generation/generator.py` that can reject a candidate (`InvalidGeneratedOutputError`). "Prompt Enforcement" means an instruction in `prompts/generation/question.txt` that guides the LLM but is not independently verified.

## Why no external terminology system was introduced

The feasibility investigation (see completion report, section 4) confirmed the only repository data with a **guaranteed, deterministic** English representation is `QuestionTarget.topic` when `target.named_entity_target` is `True` — this is exactly what WP-041 already used. `CompetitorCandidate.concept` was investigated and rejected as a second source because it is raw mixed-language evidence text, not a guaranteed English label. No other existing structured source (concept/target inventories, historical Excel, source evidence) attaches a verified English representation to arbitrary stem or distractor terminology. Building one would require either an external terminology authority (explicitly prohibited by WP-062 section 6) or fuzzy/transliteration matching (explicitly and repeatedly rejected by this project, WP-038). Per section 13's fail-closed boundary, the validator therefore enforces only what it can reliably establish, and every other case is documented above as a disclosed, not silently assumed, limitation.
