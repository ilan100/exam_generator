# WP-052 — Property-vs-Identity Strategy Selection Study

## 1. Objective

WP-051 established that target-selection filtering based on evidence sufficiency must **not** be implemented.

The critical finding was:

```text
insufficient for a distinguishing-property question
        ≠
insufficient for ANY valid question
```

For the investigated targets:

```text
Caudate Nucleus
Nucleus Accumbens
```

the available evidence did not safely expose a distinguishing property, yet historical runs still produced accepted questions through the bare-identity/naming shape.

Therefore the next architectural question is:

> **Can the system safely determine, before generation, whether a target should attempt a distinguishing-property question or should go directly to a bare-identity question?**

The desired conceptual flow is:

```text
Target
   ↓
Evidence / strategy assessment
   ↓
Known distinguishing property?
   ├── YES → property-based generation
   │
   └── NO  → identity-based generation
```

The target itself must remain eligible.

This WP is an **architectural investigation only**.

Do not modify production generation behavior unless the investigation establishes that a safe, general, deterministic strategy-selection mechanism is justified.

---

# 2. Why This WP Exists

The current behavior for some targets can be:

```text
Target
   ↓
attempt property question
   ↓
predicate is shared / ambiguous
   ↓
validator rejects
   ↓
retry
   ↓
another property attempt
   ↓
validator rejects
   ↓
identity fallback
   ↓
accepted
```

WP-051 showed that skipping the target would be wrong because the identity fallback can produce valid questions.

The possible optimization is therefore:

```text
Target
   ↓
No distinguishing property known
   ↓
Skip property strategy
   ↓
Identity question
```

This could reduce wasted attempts without reducing target coverage.

However, this must be demonstrated rather than assumed.

# 59. Final Instruction to Claude

**WP-052 is an architectural investigation into question-strategy selection.**

Do not skip targets.

Do not weaken validation.

Do not increase retries.

Do not add an LLM judge.

Do not add an external ontology.

Do not build a broad semantic parser.

Do not assume that lack of a detected property means no property exists.

The central question is:

> **Can the existing authoritative evidence safely tell us whether to attempt a distinguishing-property question or go directly to a bare-identity question?**

The distinction is:

```text
TARGET SELECTION
    =
Should we generate for this target?

QUESTION STRATEGY
    =
What kind of question should we attempt for this target?
```

WP-051 closed the first problem:

```text
Do not filter the target.
```

WP-052 investigates the second:

```text
Can we choose the strategy?
```

The desired architecture, if justified, is:

```text
Target
  ↓
Evidence analysis
  ↓
Strategy
  ├── PROPERTY → property-based generation
  │
  ├── IDENTITY → identity-based generation
  │
  └── UNKNOWN → preserve current behavior
  ↓
Existing generation
  ↓
Existing validators
```

The `UNKNOWN` branch is important.

Never force a strategy when the evidence is uncertain.

The final objective is:

```text
same or better accepted output
+
fewer wasted attempts
+
no meaningful loss of diversity
+
no loss of target coverage
```

not merely:
