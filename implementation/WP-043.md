# WP-043 — Deterministic Evidence Sufficiency and Target-Role Handling

## 1. Objective

WP-042 established that the WP-041 English-first policy is **not the primary cause** of the acceptance regression.

The remaining problems are two distinct evidence/generation boundary problems:

### Problem A — Corpos Striatum

The selected target is:

```text
Corpos Striatum
```

but its narrow anchored evidence is effectively:

```text
Corpos Striatum
```

with no useful descriptive context.

This causes generation to construct logically invalid questions, for example:

```text
Which of the following is part of Corpos Striatum?

Required answer:
Corpos Striatum
```

The validators correctly reject this.

### Problem B — Basillar artery

The evidence is richer, but the target participates in the evidence as an upstream/source entity.

Conceptually:

```text
Basillar artery
        ↓
feeds
        ↓
Superior Cerebellar Artery
        ↓
supplies the named area
```

Generation nevertheless tends to construct questions whose semantic role requires:

```text
Superior Cerebellar Artery
```

while WP-040 requires:

```text
Basillar artery
```

as the answer.

The grounding validator correctly rejects this.

---

# 2. Primary Goal

Improve the information supplied to generation so that:

1. a target has sufficient evidence to support a valid question;
2. the target's semantic role in the evidence is respected;
3. generation is not forced into a question pattern incompatible with the evidence;
4. existing validators remain strict;
5. English-first remains unchanged;
6. the three-attempt budget remains unchanged;
7. coverage remains unchanged.

The desired architecture is:

```text
Target
   ↓
Narrow evidence anchor
   ↓
Evidence sufficiency check
   │
   ├── sufficient
   │      ↓
   │   target-role analysis
   │      ↓
   │   generation
   │
   └── insufficient
          ↓
      deterministic broader evidence fallback
          ↓
      evidence sufficiency check
          ↓
      target-role analysis
          ↓
      generation
```

# 6. Problem A — Empty / Insufficient Narrow Anchor

## 6.1 Current Case

For:

```text
Corpos Striatum
```

the narrow `factual_focus` is effectively:

```text
Corpos Striatum
```

with no descriptive information.

This is insufficient to reliably construct a grounded question.

---

## 6.2 Required Behavior

Introduce a deterministic evidence sufficiency decision.

Conceptually:

```text
factual_focus
    ↓
Is there useful descriptive content?
```

If yes:

```text
use factual_focus
```

If no:

```text
use deterministic broader evidence fallback
```

---

# 7. Define "Insufficient" Conservatively

Do NOT use:

```text
LLM says evidence is insufficient
```

Do NOT use:

```text
embedding similarity
```

Do NOT use:

```text
fuzzy semantic scoring
```

The first version should use deterministic structural criteria.

For example, investigate whether:

```text
factual_focus.strip()
```

is effectively only the target representation.

If:

```text
factual_focus == target.topic
```

and contains no additional factual content, treat it as insufficient.

But do not blindly implement this exact comparison before inspecting the existing data model.

Use the simplest deterministic criterion that matches the actual architecture.

---

# 8. Broader Evidence Fallback

When narrow evidence is insufficient, retrieve a broader evidence window from the **same authoritative source evidence already associated with the target**.

The fallback must:

- preserve provenance;
- preserve source identity;
- preserve page/document metadata;
- remain deterministic;
- avoid unrelated evidence;
- avoid inventing text.

Preferred conceptual behavior:

```text
narrow anchor
    ↓
empty / insufficient
    ↓
expand within same source evidence
    ↓
obtain surrounding factual context
```

Do not introduce a new retrieval system.

---

# 9. Fallback Boundaries

The broader fallback must have a bounded scope.

Do not simply provide the entire category or entire textbook to the LLM.

Prefer:

```text
target-local evidence
```

then:

```text
small surrounding evidence window
```

then, if the architecture already supports it, a slightly broader bounded window.

Do not create an unbounded retrieval loop.

---

# 10. No Evidence Invention

If the broader evidence still does not contain usable support:

```text
do not invent context
```

The system must be allowed to conclude:

```text
insufficient evidence
```

rather than generate an unsupported question.

This is important.

A lower acceptance rate is preferable to a hallucinated medically factual question.

---

# 12. Generation After Fallback

Once broader evidence is obtained, generation should continue through the **existing WP-040 target-aware generation path**.

Do not create a separate generation path for Corpos Striatum.

The generator should receive:

```text
TARGET CONCEPT:
Corpos Striatum

TARGET LANGUAGE:
English

TARGET ANSWER:
Corpos Striatum

FACTUAL EVIDENCE:
<deterministically expanded evidence>
```

The question must still make `Corpos Striatum` the correct answer.

---

# 13. Problem B — Target Semantic Role

The second problem is fundamentally different.

For:

```text
Basillar artery
```

the evidence describes a relationship in which the target is upstream/source.

Conceptually:

```text
Basillar artery
    ↓
feeds
    ↓
Superior Cerebellar Artery
```

Generation must not assume:

```text
target = downstream entity
```

---

# 14. Do Not Automatically Infer a Semantic Role With an LLM

Do not add an LLM role classifier in this WP.

First inspect whether the existing evidence text already contains enough deterministic information to support the role.

For example, if the source sentence explicitly contains:

```text
Basillar artery gives rise to Superior Cerebellar Artery
```

the relationship can be preserved as source evidence.

Do not build a generalized medical knowledge graph in WP-043.

---

# 15. Target-Role-Aware Generation

The generation context should make the target relationship explicit enough that the model does not repeatedly generate an incompatible question.

For example, conceptually:

```text
TARGET:
Basillar artery

EVIDENCE ROLE:
The target is described as an upstream/source artery
that gives rise to or feeds another artery.

REQUIRED ANSWER:
Basillar artery
```

The exact wording should be derived from the source evidence.

Do not invent role descriptions.

---

# 16. Important Question-Generation Principle

The question must be constructed around the target's actual evidence role.

If:

```text
Evidence:
X → feeds → Y
```

and:

```text
Target = X
```

then the question should test:

```text
X
```

as the source/upstream entity.

It should NOT ask:

```text
Which artery supplies Z?
```

if the evidence supports:

```text
Y supplies Z
```

instead.

---

# 17. Example — Basillar artery

Bad:

```text
Which artery supplies the upper surface of the cerebellum?

A. Basillar artery
B. Superior Cerebellar Artery
...

Correct:
Basillar artery
```

This conflicts with the evidence.

Better question forms should be derived from the actual evidence relationship, for example a question about:

```text
which artery gives rise to / feeds / supplies another named artery
```

provided that exact relationship is supported by the source.

The exact generated wording is the LLM's responsibility.

The architecture must simply make the relationship visible.

---

# 18. Target-Answer Identity Remains Mandatory

Do NOT remove or weaken WP-040's requirement:

```text
answer must identify the selected target
```

The purpose of WP-043 is to make it possible to satisfy this requirement honestly.

The desired relationship is:

```text
evidence
    ↓
supports target role
    ↓
valid question
    ↓
target is correct answer
```

not:

```text
evidence
    ↓
doesn't support target as answer
    ↓
remove target requirement
```

---

# 19. Evidence Sufficiency Before Generation

Introduce the concept of:

```text
evidence sufficiency for target generation
```

but keep it deterministic.

The question is:

> Does the evidence contain enough factual information to formulate a question whose answer is the target?

Initially, this can be implemented through structural rules and explicit target/evidence relationships.

Do not introduce a general-purpose semantic evaluator yet.

---

# 20. Avoid Overengineering

WP-043 is NOT:

```text
Build a semantic evidence graph
```

It is:

```text
Fix two demonstrated edge cases
using the smallest deterministic architectural change.
```

Keep the implementation narrow.

# 29. Important Failure Criterion

If broader evidence does not solve `Corpos Striatum`, or if the target-role problem cannot be solved safely for `Basillar artery`, **do not force acceptance**.

Record:

```text

```

or:

```text
target-role ambiguity
```

and recommend the next architectural step.

A failed safe generation is preferable to an unsupported question.

---

# 30. Do Not Change the Three-Question Quota Logic

The system must continue to respect the existing bounded generation rules.

```text

```

```text

```

The objective is to improve the **quality of the initial candidate generation**, consistent with the architectural direction established earlier.
