# WP-047 — Target-to-Answer Contract and Identity Enforcement Study

## 1. Objective

WP-046 introduced a narrow deterministic post-generation check for parent/child distractor containment. It also exposed another important failure: for `Corticospinal Tract`, an accepted question had `Precentral Gyrus` as the answer. The question was grounded and passed existing validators, but the answer did not identify the requested target.

WP-047 must determine what constitutes a valid relationship between:

```text
requested target
question relationship
accepted answer
```

Do **not** begin by implementing `correct_answer == target`.

The first objective is to define and validate the target-to-answer contract. Only then may deterministic enforcement be considered.

---

## 2. Why This WP Is Needed

The current architecture can produce:

```text
target
  ↓
factually grounded question
  ↓
factually grounded answer
```

while still producing:

```text
answer ≠ requested target
```

Therefore factual correctness and target alignment are separate properties.

---

## 3. Critical Principle

Do not assume that `correct_answer == target` is universally required.

Some legitimate relationships may intentionally ask for:

```text
source
origin
location
function
relationship
classification
other related entity
```

For example, an origin question about `Corticospinal Tract` may legitimately have `Precentral Gyrus` as its answer.

The problem is:

```text
answer differs from target
+
the requested relationship does not justify that difference
```

---

## 4. Hard Constraints

Initially do NOT modify:

- validators;
- public/shared schemas;
- target selection;
- coverage;
- retry budget;
- English-first;
- evidence anchoring;
- WP-044 mechanisms;
- WP-046 distractor-containment mechanism.

Do NOT introduce:

- LLM target-identity judges;
- embeddings;
- fuzzy semantic matching;
- external medical knowledge;
- medical ontologies;
- target-specific exceptions;
- special handling for `Corticospinal Tract`;
- special handling for `Precentral Gyrus`;
- blanket `correct_answer == target` enforcement.

The first phase is diagnosis and contract definition.

## 12. Distinguish Three Levels

For every case distinguish:

## 20. Determine Whether the Contract Can Be Deterministic

Answer:

> Given the target, relationship, answer, and authoritative evidence, can Python deterministically determine whether the answer is valid for that target relationship?

Possible outcomes:

```text
YES
PARTIALLY
NO
```

All three are acceptable.

Do not force deterministic enforcement where the available information is insufficient.

---

## 21. Safety Criteria for Implementation

A deterministic mechanism may be implemented only if:

1. it explains multiple real cases or one clearly defined structural class;
2. it has successful controls;
3. it supports legitimate related-entity answers;
4. it does not depend on target-specific names;
5. it does not depend on one exact phrase;
6. it does not use fuzzy semantic matching;
7. it does not require an LLM judge;
8. it preserves existing validators;
9. it preserves the three-attempt budget;
10. it does not break WP-046;
11. it is deterministic and testable.

If these conditions are not met:

> Do not implement the rule.
